# 真实文字对话

正常、开发与发行入口统一使用真实聊天服务和基于官方 openai-go/v3 的 Chat Completions 适配器。首次运行不创建演示会话；没有模型配置或密钥时，应用正常启动，本地日程和历史查询仍可使用。

T11 已接通正常 `finish_reason=length` 的同运行自动续写。每次创建新的 `continuation=true` model_call，原调用保持真实 input/output、usage、成功状态和 retry_count；续写拥有自己的网络重试预算，不消耗普通模型轮数。统一 `chat.max_continue` 默认 5，缺省或 0 使用默认值，负数拒绝发布；新调用前读取当前有效配置，已用次数统计该 run 所有 continuation 记录，包含摘要续写，不增加计数字段。网络异常保留部分内容并按原故障失败，不转为长度续写。上限耗尽保存 `model_continue_limit_exceeded`，保留全部已接纳结果。

正文及思考续写依次保存原 assistant、独立 user“继续未完成的输出”、下一 assistant，各次原始输出分别保留；run.input 始终为真实用户输入。run.output 只拼接最后普通轮及其续写正文，只有思考时仍为 null。重启从实际请求中的普通轮消息前缀恢复正文边界，复用原逻辑续写和实际请求，不重复扣次、不回放事件拼正文；新正文、thinking 和工具事件追加新行，旧 seq、内容及调用关联不改写。

正常 length 的同批完整工具仍执行，截断参数登记原调用及原 input，failed/解析错误和 argument=null 原样保存，记录 warning。进度模块在原 tool_call_id 的 tool 消息中保留解析错误，附加 context_arguments 与明确的未执行说明，要求模型重新输出完整调用。JSON 格式补全只闭合已有容器/字符串，省略未完成字段或字面值，不猜业务值、不拼两次 arguments，不覆盖原 output/input 或冒充业务结果；公开 tool_result 仍为原始 output/error。所有同批结果配齐后才请求模型，此时 continuation=true，不额外插入 user 续写指令。后续完整工具使用该回复实际返回的 ID，已完成工具不重复执行。

T11 测试通过 chat.Service 公共用例、真实 SQLite、真实模型 HTTP 适配器及正式日程入口覆盖正文/thinking、混合工具批次及新 ID、上下文限定修复、默认/配置预算耗尽、普通轮正文隔离、断流不续写、重启复用及既有事件连续性；配置测试覆盖默认值、覆盖、非法更新和目录监听。沿用数据库版本 3、原五阶段三字段、HTTP 及 Flutter 契约；摘要生成仍由后续切片交付，其续写共享上述记录计数。

参数补全扫描以共享不可变栈记录语法边界，避免按每个层级反复复制闭合串；只在实际验证候选时一次构造内容。超过 encoding/json 支持的 10000 层嵌套时 context_arguments 为 null，仍通过原 ID 返回解析错误和明确未执行说明。公共用例覆盖不完整字符串、布尔值、指数数值、Unicode 转义、4096 层容器及超限片段。

R1 将完整回复接纳、模型调用开始/结束 checkpoint 及跨轮有效上下文集中在聊天模块的进度规则中。SQLite adapter 在原事务内调用这些规则，继续核验实际事实、保存 output/usage 与事件尾批、分配连续事件序号；协调器在提交成功后才采用新进度并启动工具。待提交快照复制消息、原始工具 JSON 和完成集合，保存失败不改写此前快照；实际已取得的工具结果独立保留，收尾事务沿已提交进度合并，不重执业务。

R2 将工具开始与单项结果也统一为完整进度操作。SQLite 开始及结果事务回读当前调用已提交的 checkpoint，在原事务内合入 running/原参数/关联/开始事件或实际 output/error/结果事件/原 ID 消息，再原子保存完整进度。提交成功才向协调器返回新快照；失败不采用待提交状态，已保存结果重试直接复用已提交事实。协调器不再维护第二份完成集合，也不传入批次数量来判定结束；进度按全部原请求的 ID 配对事实表达 tool_end，下一步普通模型调用、配置、等待与调度仍由协调器选择。并行结果按实际接纳次序串行合并，不增加 FIFO。

R3 将取消跳过、未确认结果及故障真实结果保留统一到聊天进度模块。正常单项结果与异常批次收拢共用原 ID 配对和阶段转换规则；SQLite 终态事务读取最新已提交调用、checkpoint 与工具事实，优先复用已保存或协调器实际取得的结果，再按取消 skipped/aborted 或 tool_result_unconfirmed 补齐缺失项。存储只负责事务内核验、事实及事件保存，不另行裁决消息接纳、中断说明或未确认结果。

开始事务失败不执行业务。结果或开始保存失败后，协调器停止启动新工具和模型，收集当前已返回查询的实际结果，其他在途查询不阻挡故障收尾，仅随原终态事务重试保存，不重执查询。未开始的取消项直接保存 skipped 最终事实和原展示配对事件，不伪造 running/tool_use。取消收尾恢复保留原成功调用及真实结果，只补齐已有请求并结束，不重新调用模型或补做查询；正常退出继续保留未完成进度。终态回滚不暴露半份进度、不释放占用，沿既有五秒间隔最多三次重试；耗尽规则不变。结果提交成功但回执丢失时，事务内最新事实优先于协调器旧快照；重复保存不重复结果或终态。

沿用数据库版本 3、原有五阶段及 context/completed_tool/last_tool 三字段格式。新模型调用清空本次工具事实，同调用恢复保留其完成集合。下一轮仍从最新已结束运行的完整快照接续，兼容过滤旧全空 assistant，保留仅思考回复、原消息顺序与工具配对；独立中断说明追加在旧轮之后、真实新输入之前，恢复已登记请求直接复用原 input。未接纳的工具片段不进入有效工具上下文，原始 output、usage、正文和思考按现有规则保留。回复接纳后、部分结果后与 tool_end 后的 SQLite 快照恢复，以及旧格式取消恢复、开始/结果/终态事务回滚、并行结果保留、提交回执丢失、快照隔离及退出恢复，均通过公开运行/会话用例、真实模型适配器和正式日程入口验证。HTTP、Flutter 和工具注册契约不变；T10 已接通完整在途工具取消，完整写入恢复仍由后续任务交付。

旧运行被后续运行取代的恢复测试保留完整的保存失败重试耗尽过程，并在新运行与重启收尾的真实提交边界模拟四秒慢存储。测试等待事务完成回执后，再从公开接口核对成功/失败终态、run_superseded、部分正文与不重发模型；事务错误直接反馈，等待仍有二十秒上限，不把普通测试的三秒轮询期限作为运行处理性能契约。

## 配置与运行

在当前实例 `--data-dir` 指定的数据目录中编辑 `config.yaml`，添加非密钥配置。例如：

```yaml
chat_model:
  - provider: deepseek
    base_url: https://api.deepseek.com
    models:
      - model: deepseek-v4-flash
        context_window: 32768
        max_output_tokens: 8192
chat:
  max_rounds: 20
  max_continue: 5
  max_retry: 3
  first_timeout_seconds: 120
  idle_timeout_seconds: 60
  tool_concurrency: 3
  tool_timeout_seconds: 30
  tool_max_retry: 3
```

`context_window` 是本地使用的上下文预算，应不大于所用模型的真实容量；`max_output_tokens` 缺省 8192，必须满足 `0 < max_output_tokens < context_window`。同一个 provider 可配置多个模型，同名模型通过 provider 区分。`base_url` 采用不带 `/chat/completions` 的 API 基址。

复制仓库 `example.env` 为同目录 `.env` 并填写密钥。密钥名由 `{PROVIDER}_{MODEL}` 转大写、非 ASCII 字母数字替换为下划线得到，例如 `DEEPSEEK_DEEPSEEK_V4_FLASH`。密钥从不进入 HTTP 响应、数据库请求记录或日志； `.env` 和模型配置的后续修改不需要重启。模型列表的 available 只表示本地配置及密钥存在，不代表上游认证成功。

打开 AI 页，选择提供方和模型后发送文字。密钥缺失时选项标为不可用；补齐后点击“刷新模型”。请求身份固定到本轮运行，重试相同幂等键始终返回原运行。

## 服务与存储

Go 启动时通过现有 PrepareSchema 初始化或备份升级数据库到版本 3；新增 `ai_sessions`、`ai_runs`、`ai_model_calls`、`ai_checkpoints`、`ai_events`、`ai_tool_calls` 六张表，原四张日程与提醒业务表保留。旧 Flutter 库升级前在原库旁生成一致性 `.before-upgrade-*.bak`，失败回滚；不转换 Wails 或未知结构。

调用模型前，短事务保存实际 input、running 和 checkpoint；流式增量满 5 条或首条等待 5 秒提交，后续增量不延后首条期限。结束、取消、错误和正常退出立即保存尾批，逐条保留原始事件，不合并或裁剪；尾批与相应调用结果和状态在同一事务保存，终态同时提交 checkpoint 和 error/end。只有成功提交的事件才供 SSE 和分页读取，事务失败不会留下已提交序号缺口。没有返回 usage 时保存 SQL NULL。会话软删除只隐藏父会话和公开子查询，不删除日程或执行事实。

HTTP 使用 `/v1/model`、`/v1/run`、`/v1/run/:run_id`、`/v1/run/:run_id/events`、`/v1/run/:run_id/event`、`/v1/run/:run_id/cancel` 与原有 session 路径。创建必填 session_id/input/provider/model，回执固定 run_id/status/output/error；概况固定十字段，错误与部分正文可以同时保留。thinking/text 仅含 content，error 含 code/message，end 仅含 status。事件页固定 events/next_after_seq/has_more；默认 10、最大 100 条，事件序号与 SSE 共用。

## 当前切片边界

T09 已接通工具有界调度、单次超时及有限重试。`chat.tool_concurrency` 默认 3，调度持续读取当前值（空闲等待最长约 100 毫秒重读），调低不取消已开始尝试；密钥文件读取失败或模型配置暂时不可读时保留本批最近有效工具参数，不扩大并发或重试预算。可并行工具允许执行区间重叠，串行工具与其他有效尝试互斥。退避及已超时尝试释放名额，不形成队首屏障、不保证 FIFO、不保存队列顺序；业务依赖仍分不同模型轮次表达。

`chat.tool_timeout_seconds` 默认 30，每次实际执行前读取、尝试内固定。期限到达立即向业务 context 发出取消并结算，释放有效执行名额，不等待忽略 context 的工具返回；取消信号不证明副作用已经回滚。协调器以独立尝试 token 隔离迟到结果，旧尝试不能覆盖新尝试或再次推进运行。工具 goroutine 只返回事实，协调器持有唯一结算权，最终结果仍交统一进度保存。用户取消阻止后续启动与重试，在途尝试等待原结果或原期限；T10 已接通取消与只读回执核对；正常运行的完整写入恢复仍属后续切片。

`chat.tool_max_retry` 缺省 3，含义为首次之外三次，显式 0 仍允许首次执行；并发和超时的 0 使用默认值，三个配置均拒绝负数。每个逻辑工具在首次登记时固定 max_retry，之后沿原记录、参数与适用幂等键使用剩余预算。只有 tool_timeout 或工具明确返回的 tool_temporary_error 可重试，参数、业务、未分类错误直接形成最终失败；中间故障保存 retry_wait/error/next_retry_at，按 5/10/20 秒指数退避，不加入 completed_tool、不生成最终 tool_result 或模型 tool 消息。实际错误重试与已有未确认调用的恢复重执行共用预算，重试前增加 retry_count 并与 running/tool_use 同事务保存；达到上限的最后一次许可仍执行。重启保留退避期限与已用次数，不清零、不重复扣次。

超时逐项结算，每次保存返回后先重新接纳已返回的工具事实，再选择下一个超时尝试。其他工具若已在原期限内成功返回，即使期限在保存等待期间过去，也保留实际成功结果；真正超时后才返回的结果仍按原 token 与期限隔离。

正常退出与用户取消分别处理：退出期间在途工具达到原期限或返回暂时故障，且尚有预算时，保存 retry_wait/错误/next_retry_at，保留未完成工具配对，不因退出写成最终失败。退出不再启动尝试或下一轮模型；重启后沿原调用身份、参数和固定预算等待原期限，再实际增加重试次数并执行。用户取消、会话删除仍停止后续重试；已明确不可重试或预算耗尽的实际错误仍保存为最终工具结果。

退避取消与慢保存的自动化通过真实提交边界、工具返回信号和原 context deadline 同步，不依赖三秒内轮询到短暂状态，或用固定休眠猜测已返回与已超时的先后。慢保存场景使用两个独立尝试覆盖原并发窗口，先确认工具返回，再等待它的期限经过后释放保存；提交后终态读取使用单独的有界等待，不改变业务超时与退避配置。测试继续核对实际状态、原始结果、执行次数、事件数量与整批模型回填。

永久错误与参数错误的四工具回归使用 30 秒终态观察看门期限，完成即返回；该期限不改变工具超时或重试策略。用例核验两次实际工具执行、两次模型请求、四项公开结果的原错误类别及开始/结果事件配对；失败时在停止服务前以共用两秒读取期限输出 run 状态、模型调用 checkpoint/完成集合及各工具状态与重试事实，便于区分慢持久化和未完成推进。

只有最终成功/失败才合并配对消息与工具完成集合，整批完成才继续模型。取消退避沿统一规则保存 skipped/aborted；最终结果清除 next_retry_at。新增自动化通过 chat.Service 公共用例、真实 HTTP 模型适配器/SQLite/日程业务及可控阻塞工具，验证并发缩扩容、串行区间、固定/热读超时、默认三次退避、重启预算、耗尽、取消、迟到隔离、慢结算期间及时结果保留、退出期间暂时故障/超时的重启接续及正式删除已提交后的原键回执复用；不变更 HTTP、Flutter 或数据库结构。

T08 已接通带版本和幂等保护的日程删除，生产入口在同一个 Registry 中注册六个日程工具。固定系统提示要求明确完整且目标唯一时直接执行、缺字段或多目标先澄清，执行结论以实际工具结果为准；提示随实际请求参与持久化和预算，原始 run.input 保持原文。

| 工具 | 写入能力 |
| --- | --- |
| `create_schedule` | 必填 name/type。single 需要 notifyTime；period 需要字符串数组 cron 和布尔 open；两种规则字段不混用，description 可选。 |
| `update_schedule` | 必填唯一 id/expectedRevision；可修改 name/description/notifyTime/cron/open，至少一项。省略的字段保留，description 空字符串清空，不支持转换日程类型。先查询目标和版本，再以取得的结果调用。 |
| `delete_schedule` | 必填唯一 id/expectedRevision；通过 App.DeleteScheduleVersion 正式软删除，停止已有提醒的投递、撤销未来待投递提醒，保留到期历史及其原文。 |

notifyTime 接受 RFC3339、北京时间 `YYYY-MM-DD HH:mm`、`今天/明天/后天/昨天 HH:mm`。模型将“明天下午三点半”规范为“明天 15:30”，不预先换算绝对日期；后端每次实际解析才读取北京时间，不冻结到 run.created_at。缺日期或时刻先澄清，不取整秒级时间；最终可写性由正式规则校验。已保存的明确时间及实际结果按原事实复用，跨午夜恢复不重新解释成功结果。

两个写工具均为 dangerous=false、串行执行，调用 App.WriteSchedule 时业务 key 为空，工具键为 SQL NULL。正式业务统一处理规则、expectedRevision 和提醒更新；返回完整规则/revision 及 mutation 提醒变更摘要。冲突、不存在和规则拒绝分别回填 revision_conflict、schedule_not_found、invalid_schedule；参数或业务失败不自动重试。多条操作独立成功/失败，不整批回滚；有依赖的操作取得前一步结果后分模型轮次生成。

工具只负责定义、参数转换、业务调用与原始结果，开始/回填/异常配对和批次完成仍沿 R1–R3 统一进度，不自行构造 checkpoint。不按名称或时间去重，不承诺无键写入恰好执行一次，也不提前交付 #129 的完整写入恢复。HTTP、Flutter 和数据库版本 3 不变。自动化以 chat 公共用例、真实模型适配器、SQLite 和正式 App 写入验证；时钟边界注入午夜，已提交结果边界保存一致数据库快照后重建服务核验复用。
