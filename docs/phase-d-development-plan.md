# 阶段 D 开发规划：3 个新增接口

## 1. 目标与职责

完成真实提醒、全期间恢复、通知点击、托盘、进程管理和登录自启。

**登录自启由 Flutter 管理**：直接读取配置、应用 Windows 启动项并展示执行结果。移除两条桌面偏好接口，Go 不增加对应配置字段、偏好用例或结果回填。

Go 继续拥有日程规则、触发事实和投递状态；提醒展示结果仍须回流 Go。

按用户最新决定，任务分组、展示次数、尝试成员和恢复位置只保存在运行内存中，重启后重新建立，不要求跨重启保留预算或尝试回执。预加载状态复用 `notifications.status=loaded` 保存；直接修改原 001 的 status CHECK 支持 pending/loaded/sent/failed，继续使用版本 2，不新增表、字段、迁移、中间表或 RuntimeStore。使用单个 Flutter 通知执行者，不引入租约和周期性心跳；失败由执行结果、退出事件及本次运行内的重试处理。规则历史、当前提醒状态、确认及永久停止仍沿用现有数据库，failed 重加载后转为 loaded，失败尝试历史不跨重启保留。

阶段 D 使用显式数据目录及手动迁移后的数据库；自动迁移、正式用户目录默认值和安装交付留给 E。

D1 的 30 秒窗口扫描、loaded 状态、近期首提醒即时入队、到点核验和完整分组见 [D1：分钟调度方案](phase-d1-minute-scheduler.md)。已完成本地及 Apifox 验收，见[验收记录](phase-d1-validation.md)；运行和清理由 service.App 管理，main 仅装配。

## 2. 配置与接口

### Flutter 直接读取自启配置

沿用 `config.yaml`：

```yaml
desktop:
  start_on_login: false
```

- Flutter 使用 [yaml 3.1.4](https://pub.dev/packages/yaml/versions/3.1.4) 读取 `desktop` 配置节；缺少文件或字段时默认 `false`。
- 启动层将配置目录解析为绝对路径。托管模式两端使用相同 `--data-dir`；开发外连模式显式指定仓库根目录。
- Flutter 在启动及配置文件变化时读取并协调启动项，监听需覆盖文件被原子替换的情况。
- 配置解析失败时显示错误，保留已有系统应用状态；注册或移除失败时显示未生效并允许重试。
- 自启应用结果保存在 Flutter 运行状态和本地日志中。阶段 D 通过配置文件调整，不增加配置编辑页面。
- 开启后启动完整 Flutter 宿主及 Go 子进程，进入托盘；手动启动显示窗口，明确退出不立即重启。

### 新增 HTTP 接口：3 个

| 接口 | 职责 |
|---|---|
| `POST /api/v1/notifications/claim` | 从本次运行的内存队列领取完整分组；返回任务类型、当前进程有效的 attempt ID 和平台标识。不维护租约或心跳。 |
| `POST /api/v1/notifications/delivery-attempts/:id/start` | 展示前重新检查资格，冻结实际成员并消耗一次预算，返回 Go 生成的展示文案；重复请求幂等。 |
| `POST /api/v1/notifications/delivery-attempts/:id/results` | 按当前进程的 attempt 回填实际成员投递结果；同一进程内识别重复结果，已成功结果不降级。Go 重启后不恢复或裁决旧 attempt。 |

执行开始、结果回填和用户确认分别承担不同状态转换，保持独立。

### 扩展已有查询

- 提醒列表增加当前进程有效的 `deliveryTaskId`、可选 `attemptId` 和游标筛选。分组来自内存；组内提醒仍通过已有事实表查询，原待确认查询保持兼容。Go 重启后旧分组及尝试身份失效。
- 复用 `OccurrenceView` 和分页响应。游标绑定任务、尝试及查询用途；附 attempt ID 时读取该次展示的成员快照。
- 日程本组合快照及组分页增加恢复进度。现有 `total` 表示已持久化记录数量，完整遗漏数量尚未确定时单独返回未知值。
- `/health` 增加实例身份、API 版本和能力信息。
- 单条详情、日期/月历、规则变更及确认继续使用已有接口。
- 上述提醒视图的 `deliveryStatus` 增加 loaded 枚举，表示预加载/等待执行，不代表展示成功；D1 实施后先通过 Apifox 验证，再进行 Flutter 状态适配。

## 4. 状态规则、默认值与验收

必须落实：

- 同一分钟成员完整分组，处理批次和认领上限不能拆成多条通知；单条显示名称时间，多条只显示数量。
- 恢复按历史生效区间展开，排除暂停期间及已成功投递记录。完整历史与可投递成员分别统计；全部整理完成后发送唯一准确汇总。
- 本次运行内，未开始的遗漏任务转入汇总，已开始任务保留当前身份和计数。暂停、删除及确认停止后续展示，不抹去已保存业务历史或伪造失败。
- 调度生成独立于投递结果和用户确认。回填只更新执行事实，确认只更新完成事实。
- 加载写入 loaded，到点冻结文本并核验完整分钟后才开放投递；loaded 不表示展示成功。规则变更、停止及确认使尚未开始成员失效，重扫不重置展示预算。
- Go 或 Flutter 重启后不恢复尝试及回执日志；依据已有提醒投递结果重建内存队列。平台已展示但结果尚未回填时崩溃，后续运行允许再次展示。
- Go 重启不能跳过旧 loaded；按计划时间重加载、核验或恢复。休眠及扫描间隙登记后交 D3，固定前后 30 秒窗口不承担全历史恢复。
- 历史回溯以可证明的版本边界为依据，未记录的早期规则变化无法还原。

工程默认值：

- 扫描间隔 **30 秒**，正常窗口为 **当前时刻前后各 30 秒**；创建/修改/恢复提交后的 **未来 1 分钟**首提醒即时入队，到点由定时器唤醒并核验完整分钟。
- 领取间隔 **1 秒**，每次最多 **20 个完整任务**，不设置租约或心跳。
- 每次运行内最多 **4 次展示尝试**；失败后等待 **5、30、120 秒**。重启后重新计数，不要求跨重启累计；本次运行的结果重传不算新的展示。
- 恢复每事务最多 **500 条记录**，查询每页 **50 条**。
- 托管启动超时 **10 秒**，优雅停止超时 **5 秒**；开发模式保持手动 Go 的进程所有权。
- 平台验收固定 Flutter **3.47.0**、window_manager **0.5.2**、tray_manager **0.5.2**、flutter_local_notifications **22.3.1**，提交 lockfile；保留本机 master SDK。

验收覆盖分钟合并、长时间离线恢复、规则变更与恢复并发、投递与停止竞争、重复及迟到回执、断网和崩溃、休眠、托盘与单实例、进程清理，以及配置缺失、非法配置、文件替换、自启应用失败和重试。

完成 Go 格式、vet、测试及调度并发 race 检查，Flutter 格式、analyze、测试和 Windows release 构建；保存 Apifox 报告与真机证据。平台接受展示请求才可记录 `sent`，用户阅读与确认保持独立。
