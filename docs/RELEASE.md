# TimeCue Windows 使用与更新

## 启动

请将 ZIP 解压到一个完整目录，并保留其中所有文件。双击 `timecue_desktop.exe` 启动，发行包默认使用托管模式，由应用管理同目录的 `timecue-core.exe`。默认数据目录是当前 Windows 用户的 `%LOCALAPPDATA%\TimeCue`。

关闭窗口会将 TimeCue 隐藏到系统托盘。需要结束应用时，请在托盘图标菜单中选择“退出”。更新前也必须先从托盘退出，确保程序文件不再使用。

正式发行目录包含 `update.py`、`manifest.json` 和 `timecue-core.exe`。主实例窗口成功创建后，应用会将该目录登记到当前用户的 `TIMECUE_INSTALL_DIR` 环境变量。每次从另一个正式发行目录成功启动，都会更新登记，因此多份安装并存时，更新目标是最近一次正式启动的安装目录。移动安装目录后，在新位置启动应用即可重新登记。

## 更新

更新只替换发行清单管理的程序文件，并保留额外的用户配置、数据库和日志。建议在更新前备份重要数据。

1. 从托盘菜单退出旧版 TimeCue。
2. 将新版 ZIP 解压到一个与旧安装目录没有包含关系的新目录。两个目录不能相同，也不能一个位于另一个里面。
3. 不要先启动新解压目录中的 `timecue_desktop.exe`。它会将安装路径登记为新目录，更新脚本随后就无法用它定位旧安装。
4. 在新版目录打开终端，运行 `python update.py`。脚本从当前用户的登记值定位旧安装，校验新包文件的 SHA-256，然后执行更新。

如果旧版还没有登记安装目录，请在新版目录运行以下命令，将路径替换为旧安装目录的绝对路径；随后再运行更新命令：

```powershell
python update.py --register "D:\TimeCue"
python update.py
```

脚本需要 Python 3.9 或更高版本；Python 解释器不包含在 ZIP 中。Windows 已安装 Python 启动器且对应版本可用时，也可以用 `py -3` 代替命令中的 `python`。更新只写入当前用户可写的安装目录，不需要管理员权限。

脚本优先读取当前用户的持久登记值，避免使用打开终端时遗留的旧环境变量。它会在同一卷的临时目录暂存文件，完成 SHA-256 校验后再替换。旧安装有发行清单时，只清理旧清单拥有而新版不再包含的文件；未登记的额外文件会保留。旧安装缺少清单时，脚本只更新新包中的同名文件，不猜测或清理其他文件。遇到占用文件或与未登记文件冲突时，脚本会明确失败，不会结束其他进程。替换失败时会尝试回滚；如果回滚也失败，终端会给出保留的备份目录位置以供恢复。

## 开发外连与启动问题

发行包默认使用 managed。开发或联调时，可以显式指定数据目录，并连接手动启动的 Go 服务：

```powershell
timecue_desktop.exe --backend=external --data-dir="D:\TimeCueData"
```

退出应用不会停止手动启动的 Go 服务。若固定端口 `127.0.0.1:10086` 已被其他程序占用，TimeCue 会报告启动失败；请先处理端口占用，不要依赖应用结束其他程序。

## 构建与检查

开发者可在仓库根目录使用 `scripts/build-release.ps1` 构建 Windows x64 完整 ZIP。脚本使用当前环境中的 Go、Flutter 和 Python；正式发布由 stable CI 验证。详细检查命令见仓库中的贡献规范：<https://github.com/dengweitian0-svg/TimeCue/blob/dev/docs/CONTRIBUTING.md>。CI 会运行更新脚本标准库测试、Flutter stable 检查和 Windows 原生 CTest。

发布前请在隔离目录解压候选 ZIP，手动检查完整目录启动、托盘退出、默认数据位置、更新成功、程序占用时的失败提示和用户文件保留情况。需要真实 Windows 桌面交互的验收应在目标系统执行并单独记录；CI 结果不代表这些人工平台检查已经完成。
