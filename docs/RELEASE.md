# TimeCue Windows 使用与更新

## 启动

请将 ZIP 解压到一个完整目录，并保留其中所有文件。双击 `timecue_desktop.exe` 启动，发行包默认使用托管模式，由应用管理同目录的 `timecue-core.exe`。默认数据根目录是 Flutter EXE 所在目录，从快捷方式或其他工作目录启动也相同。显式 `--data-dir` 优先，相对目录按启动工作目录解析；配置文件、数据库及日志路径规则保持一致。不会自动迁移或搜索旧 LocalAppData 数据，如需继续使用旧目录，请显式传入。

所有 Debug、Profile、Release 构建均接受运行时 `--env=test|release`：省略或 release 连接 `127.0.0.1:10086`，test 连接 `127.0.0.1:1145`。托管宿主自动向 Go 传递环境，非法或空值启动失败。环境只影响端口，相同目录共用数据；需要隔离时显式指定不同数据目录。环境不改变单实例身份，重复启动的显式冲突会被拒绝，切换环境需先从托盘完整退出。

关闭窗口会将 TimeCue 隐藏到系统托盘。需要结束应用时，请在托盘图标菜单中选择“退出”。更新前也必须先从托盘退出，确保程序文件不再使用。

正式发行目录包含 `update.py`、`manifest.json` 和 `timecue-core.exe`。主实例窗口成功创建后，应用会将该目录登记到当前用户的 `TIMECUE_INSTALL_DIR` 环境变量。每次从另一个正式发行目录成功启动，都会更新登记，因此多份安装并存时，更新目标是最近一次正式启动的安装目录。移动安装目录后，在新位置启动应用即可重新登记。

## 更新

更新只替换发行清单管理的程序文件，并保留额外的用户配置、数据库和日志。建议在更新前备份重要数据。

1. 从托盘菜单退出旧版 TimeCue。
2. 将新版 ZIP 解压到一个与旧安装目录没有包含关系的新目录。两个目录不能相同，也不能一个位于另一个里面。
3. 不要先启动新解压目录中的 `timecue_desktop.exe`。它会将安装路径登记为新目录，更新脚本随后就无法用它定位旧安装。
4. 在新版目录打开终端，运行 `python update.py`。脚本从当前用户的登记值定位旧安装，校验新包文件的 SHA-256，然后执行更新。

如果旧版还没有登记安装目录，请在新版目录运行以下命令，将路径替换为旧安装目录的绝对路径；随后再运行更新命令：

```powershell
python update.py --register "D:\TimeCue"
python update.py
```

脚本需要 Python 3.9 或更高版本；Python 解释器不包含在 ZIP 中。Windows 已安装 Python 启动器且对应版本可用时，也可以用 `py -3` 代替命令中的 `python`。更新只写入当前用户可写的安装目录，不需要管理员权限。

脚本优先读取当前用户的持久登记值，避免使用打开终端时遗留的旧环境变量。它会在同一卷的临时目录暂存文件，完成 SHA-256 校验后再替换。旧安装有发行清单时，只清理旧清单拥有而新版不再包含的文件；未登记的额外文件会保留。旧安装缺少清单时，脚本写入新版清单中的文件，保留其他旧文件。遇到占用文件或与未登记文件冲突时，脚本会明确失败，不会结束其他进程。替换失败时会尝试回滚；如果回滚也失败，终端会给出保留的备份目录位置以供恢复。

## 开发外连与启动问题

在解压目录打开两个 PowerShell 窗口。先在一个窗口启动 Go，待服务就绪后，在另一个窗口启动桌面端。两个命令使用同一数据目录。

```powershell
.\timecue-core.exe --env=test --data-dir="D:\TimeCueData"
.\timecue_desktop.exe --env=test --backend=external --data-dir="D:\TimeCueData"
```

退出应用不会停止手动启动的 Go 服务。手动 Go 省略数据目录仍使用 Go EXE 所在目录；前后端需声明同一环境，不会自动探测其他端口。若所选固定端口 `127.0.0.1:10086` 或测试端口 `127.0.0.1:1145` 已被其他程序占用，TimeCue 会报告启动失败；请先处理端口占用，不要依赖应用结束其他程序。

## 构建与检查

在仓库根目录运行 `.\scripts\build-release.ps1` 构建 Windows x64 完整 ZIP。打包使用 Go 和 Flutter，每次都会重新编译随包交付的 Go 服务。Python 用于运行更新脚本及相关检查。正式发布由 CI 使用 Flutter stable 构建验证，检查命令见[贡献规范](https://github.com/dengweitian0-svg/TimeCue/blob/dev/docs/CONTRIBUTING.md)。

打包前会检查 Release 构建目录，发现数据库、日志、配置、隐藏 `.env` 或链接时明确失败，不创建发行暂存目录或 ZIP，也不删除源数据。直接运行构建目录中的主程序可能产生这些文件；开发验证建议显式指定独立 `--data-dir`。遇到此错误先备份并移出提示的运行数据，或使用未运行过的干净构建目录，再重新打包；`-SkipFlutterBuild` 同样执行检查。

发布前请在隔离目录解压候选 ZIP，手动检查完整目录启动、托盘退出、默认数据位置、更新成功、程序占用时的失败提示和用户文件保留情况。需要真实 Windows 桌面交互的验收应在目标系统执行并单独记录；CI 结果不代表这些人工平台检查已经完成。
