# 交互规则与原型契约

## 最小稳定规则

遵循仓库架构方法论：先确定状态所有权和合法转换，再组织可替换实现。

1. 消息查看和处理是独立状态。只有确认成功才能将消息移出待处理列表。
2. 消息确认幂等；重复或并发请求对同一消息只产生一次状态变化。
3. 窗口可见性、后台运行阶段、就绪状态、消息处理状态独立。
4. 所有持久化经适配器完成；页面和控制台不能旁路写入。
5. 平台结果回流：目录实际生效值、清理失败、通知激活均回填应用状态。
6. 核心流程依赖窄契约，不依赖真实 Wails 或浏览器存储实现。

## 状态所有权与操作分类

| 操作 | 类别 | 状态所有者 | 规则 |
| --- | --- | --- | --- |
| 切换设置分类、修改未保存输入 | 页面状态 | React 页面 | 不持久化、不确认消息 |
| 读取消息、选择详情 | 应用用例 | Controller + MessagesPort | 只读；失效目标显式反馈 |
| 确认消息 | 应用用例 | MessagesPort | 保存成功后移出；失败保留并允许重试 |
| 保存配色、关闭偏好 | 应用用例 | SettingsPort | 保存成功才更新生效值 |
| 选择目录 | 平台交互 | SettingsPort | 模拟返回路径或取消；不自动保存 |
| 保存日志/备份目录 | 应用用例 + 平台结果 | SettingsPort | 成功立即生效；失败返回实际生效目录 |
| 隐藏、最小化、恢复窗口 | 平台生命周期 | WindowPort | 不改变消息处理状态 |
| 再次启动 | 平台生命周期 | WindowPort | 激活唯一模拟窗口 |
| 正式退出 | 平台生命周期 | WindowPort | 停止提醒→清理通知→释放资源 |
| 系统通知点击、窗口就绪 | 平台事件 | ActivationPort | 先缓存定位请求，待就绪消费 |

## 原型端口

`src/contracts.ts` 为本原型新增契约，不表示现有 Go 后端已经提供这些接口。

- `SettingsPort`：读取设置、保存配色/关闭偏好、选择目录、保存指定类型目录。
- `MessagesPort`：读取有序待处理列表、读取目标详情、单条幂等确认。
- `WindowPort`：读取平台状态、关闭、最小化、恢复、再次启动、退出。
- `ActivationPort`：通知目标激活与就绪状态变化。
- `Ports.subscribe`：把平台或外部页签的结果回流至控制器。

后续 Wails 适配器实现这些窄端口即可替换 `MockAdapter`；生产代码应使用后端事务和真实平台事件，不能直接复用模拟本地存储作为生产事实来源。

## 通知状态转换

- 点击系统通知：运行中恢复主窗口；就绪时加载指定目标。未就绪时保留最近一次定位请求，后续点击替换先前请求。此队列策略属于本原型交错场景的明确约定。
- 初始加载按时间倒序，同刻保持稳定列表顺序；查看、打开、切换不触发确认。
- 确认开始时禁用重复提交；成功后优先同刻下一条，否则选择列表中第一条剩余消息；没有消息则显示空状态。
- 已确认目标显示“这条提醒已经确认”；不存在目标显示“这条提醒已不存在”；均无伪造正文，并有返回列表入口。
- 确认中收到新的激活事件时，新激活拥有选择权；确认完成仍刷新待处理列表，避免保留已确认条目。
- 请求序号阻止迟到的详情/列表响应覆盖新的选择；场景 generation 阻止重置前的操作污染新数据。
- 同刻逐条通知与汇总通知是独立评审分支。汇总点击定位第一条，不执行批量确认。

## 目录设置

日志与备份各自维护：当前生效值、待保存输入、忙碌状态、结果反馈。无数据库路径编辑入口。

成功后立即显示新目录。旧文件不自动迁移、删除，也不继续承担读写；模拟仅验证界面契约，不执行文件操作。失败保留输入；`PrototypeError.effectivePath` 是适配器返回的实际生效值。验证失败通常仍是旧值；模拟切换失败明确返回临时目录，证明页面不能假定回退。

选择取消不修改输入或生效值。保存中禁用输入、选择及重复提交。重新进入页面或刷新后从适配器读取已生效值。

## 窗口与退出

关闭偏好默认隐藏到托盘，保存后才生效。隐藏与最小化保留后台运行；托盘有打开、退出。再次启动恢复唯一窗口。

显式退出或已保存的退出偏好进入同一停止流程。清理成功后 `notifications=[]`，桌面无 TimeCue 残留通知。失败进入 `cleanup-failed`，保留残留通知，给出重试入口，不显示清理成功。

模拟不承诺退出后的通知冷启动。停止后点击残留通知返回明确错误，评审者可显式启动应用；真实行为由 #14 验证。

## 持久化、日志与运行差异

`MockAdapter` 在 `timecue:issue-28:v1` 保存配色、关闭偏好、目录生效值和消息处理结果，也保存模拟平台状态以便两个页签协作。存储损坏或不可写明确返回失败，不静默覆盖。控制台负责重置恢复。

浏览器不具备 Go `slog`，因此本原型在系统边界用结构化 JSON `console` 记录最终错误及确认完成里程碑；不记录目录、消息正文或个人信息。真实接入应由宿主使用既有 `slog` 链路。高频 UI 更新不写日志。

模拟使用固定数据和短延迟，真实 HTTP/Wails、数据库事务、Windows 清理的失败和重试机制不同。统一契约位置，保留平台运行差异。跨页签存储事件用于演示，不能提供真实多进程事务保证。
