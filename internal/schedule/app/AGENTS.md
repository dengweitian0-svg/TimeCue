# internal/schedule/app

- 本目录负责编排日程应用用例，并定义应用层与外部实现之间的窄契约。整组取消/恢复通过 `ScheduleCanceller`、`ScheduleRestorer` 和 `ScheduleActionRequest` 接入；动作 DTO 只暴露 `schedule_id`、`open`、`revision`、`updated_at_utc`。
- 当前文件：
  - `contracts.go`：`ScheduleStore`、独立的日程/例外更新端口、取消/恢复端口、例外读取端口、`ScheduleDeleter`、`Clock`，以及创建、更新、删除、例外操作、列表请求和受控响应 DTO。
  - `service.go`：创建、更新、删除、读取、分页列表和时间边界查询用例。
  - `recurring.go`：重复整组编辑的定义合并和领域校验，保持未触及字段及原始发生身份。
  - `json.go`：`encoding/json/v2` 的创建、更新、删除、取消/恢复和变更预览请求解码，以及日程、列表、时间边界、例外操作、预览和错误响应编码边界。
  - `preview.go`：只读变更预览的操作校验、变更后投影、目标批次选择和冲突投影。
  - `coordinator.go`、`reminder_scheduler.go`：日程变更协调 epoch、唯一最近计时器、提醒占用/通知/结果回写和运行状态。
  - `*_test.go`：验证创建、更新、删除和读取用例编排、契约替换、分页默认值和 JSON 行为。
- `Service.CreateSchedule` 必须先清理标题、检查必填字段和依赖，再只读取一次时间快照，完成领域校验后才调用 `ScheduleStore.CreateSchedule`。
- `Service.UpdateSchedule` 必须校验标识、期望版本和支持的字段，预读日程以补齐缺失端点并确认类型，再只读取一次时间快照；领域校验完成后才调用独立的 `ScheduleUpdater`。
- `Service.DeleteSchedule` 必须校验标识和期望版本，通过独立的 `ScheduleDeleter` 执行永久删除，并在失败时保留存储层已读取的标题。
- `Service.GetSchedule` 必须通过例外读取端口返回已持久化的取消例外；只过滤 `open=0` 记录，不要求其原位置仍能由当前规则计算，也不能用空结果掩盖读取失败。
- 列表用例使用稳定默认 `limit`，拒绝负数；分页游标的具体编码属于存储实现，应用层只传递请求和结果契约。
- DTO 是对外的受控视图；转换时不得暴露领域原始内部字段、数据库连接或底层错误细节。
- JSON 边界必须区分缺失字段与显式零值，严格拒绝非法数值和非对象的创建、更新、删除请求；错误响应只输出业务分类、消息、字段和允许的时间边界。
- 本目录不得直接调用 `time.Now`、SQL、文件系统或具体日志实现；新增外部能力应先扩展窄接口并保持生产实现可替换。
- 创建请求沿用 `start_unix/end_unix` 表示首次实际起止；省略 cron 创建单次，非空 cron 创建重复且必须提供 `until_unix`。该截止瞬间按一次快照的显式时区转换为包含式本地日期，不要求分钟精度。
- 更新请求支持重复定义的 cron、标题、首次起止和截止日期同类型编辑；省略字段保持原值，显式 null cron/截止日期返回 VALIDATION，单次携带重复字段仍拒绝。只更换 cron 时不修改其余业务字段，成功后 revision 加一并更新审计时间。
- 日程的 `notes` 是可为空的普通文本；整组更新显式提供时替换父日程备注，例外更新显式提供时替换当前发生备注。
- `UpdateOccurrence` 使用 `(schedule_id, original_date)` 读取当前例外或规则基础发生，补齐缺失端点和文本后只向存储提交完整快照；基础规则不匹配且不存在例外时拒绝写入。
- 例外更新使用父日程 `expected_revision`，存储实现负责在同一事务内写入例外并递增父版本；返回 DTO 只暴露实际起止、原始日期、文本和新版本。
- `CancelOccurrence` 和 `RestoreOccurrence` 使用同一稳定身份和父 revision；空取消例外只有在当前规则重新产生该身份时才能被恢复删除，完整快照恢复为开放例外。例外动作结果同时回流父组 `schedule_open`。
- `UpdateSchedule` 不删除或重建例外记录；重复日程整组编辑前读取当前例外数量，并在成功响应的 `preserved_override_count` 中返回该数量。
- 预读发现旧 revision 时返回 STALE_REVISION，不调用更新端口；存储事务仍承担最终并发守卫。非法规则或合并后的日期/端点校验失败均不得写入。
- `ScheduleDTO.until_date_local` 在单条读取、创建/更新响应和列表中均返回 `YYYY-MM-DD` 或 null；JSON 创建/更新边界都保留 cron 和 until_unix 的存在性。
- `ScheduleDTO.month_end_policy` 在单条读取、创建/更新响应和列表中返回 `clamp` 或 null；该字段由后端根据 cron 生成，创建/更新请求不接收该字段。
- 重复更新先合并完整定义，再依据新 cron 通过领域校验生成或清空 `month_end_policy`；日/周/月之间可互换，cron 未修改时策略保持不变。

- ListOccurrences 只读取一次 Clock.Snapshot，校验 [from_unix,to_unix) 与查询上界，并通过 generation 绑定的游标分页；查询不得调用实例或提醒写入能力。
- `PreviewChangeRequest` 用 `operation` 区分布局：新建、整组编辑和整组恢复使用顶层 `schedule_id/expected_revision`，单次操作额外携带 `original_date`；编辑载荷复用正式请求字段，缺失、非法或多余载荷都返回 VALIDATION。
- 提醒调度只能维护一个全局最近计时器和每个日程一个最早批次；发送前后必须校验 revision、epoch、开放状态、稳定身份、实际到期时间和 5 秒有效窗口。claim 后通知提交前的失败只能回写 `skipped`，通知失败回写 `failed`，结果回写失败必须暂停调度并通过状态查询暴露。
- 日程创建、编辑、删除、例外更新/取消/恢复及整组取消/恢复的正式写入必须先经共享 `MutationCoordinator` 失效旧候选；失败和成功提交均唤醒调度器重新读取事实。
- `ConflictCheckDTO` 必须同时表达明确状态、是否真的检查过、原因和命中的冲突身份；创建、整组编辑、整组恢复和单次编辑/恢复的响应通过可空 `conflict` 返回基于已提交事实计算的结果，未执行检查时不得把空冲突当成“整个系列永远无冲突”。
- `Service.PreviewChange` 必须只读：复用创建、整组编辑和单次编辑的正式校验入口，只调用 `GetSchedule`、`GetOccurrenceOverride` 和 `ListOccurrenceSources`，不得调用任何写端口；预览通过 `HasMore` 说明是否只检查了最近批次。
- 预览目标批次只从本次操作的日程出发：整组操作检查该日程变更后的下一次发生，单次操作只检查指定身份；冲突比较必须覆盖全部日程定义，检索下界回看最长持续时间以覆盖跨天实例。单次目标已在过去、父组关闭或变更后不再产生发生时必须返回未检查状态和原因，不能改查其他发生。
- 创建、整组编辑、单次编辑、整组恢复和单次恢复必须在事务提交成功后才返回结果；提交后的 `conflict` 必须重新读取已提交事实并在同一 generation 上计算，不得复用预览或预读结果。冲突是正常结果，不阻止保存或恢复；提交失败仍按原事务语义返回错误且不产生事实变更。取消整组和取消单次不产生发生，不返回冲突结果。

- `MutationCoordinator` 统一拥有运行时状态、`epoch` 和唤醒信号；状态只允许 `running`、`suspended`、`stopping`，生命周期事件通过 `RuntimeEvent` 进入协调器。`suspend`、`resume`、`clock_changed` 和 `stop` 的有效状态变化必须使旧提醒候选失效，重复状态事件保持幂等。
- `ReminderScheduler.ApplyRuntimeEvent` 是生命周期事件进入提醒派发的唯一应用边界：暂停或停止清空候选并关闭派发资格，恢复和时钟变化从当前环境严格向后重建，不补发过去发生。到期回调还必须检查 `TimeSnapshot` 的环境异常事实，异常时拒绝发送并重建。
- 提醒调度始终只维护一个全局最近计时器和每个日程一个最早候选；候选携带日程 revision 与 runtime epoch，通知提交使用可取消 context。`reminder_attempts` 的稳定发生身份负责持久化去重，发送结果只回写 `submitted`、`failed` 或 `skipped`。
- 所有正式业务写入必须通过 `MutationCoordinator.BeginMutation` 取得准入；`stopping` 之后返回 `RUNTIME_STOPPING`，查询和只读预览不经过该准入，也不依据提醒派发状态改变结果。
