# internal/schedule

- 本目录承载日程能力，按领域规则、应用用例和时间环境拆分，禁止把持久化细节下沉到领域层。
- 当前结构：
  - [`domain/`](domain/AGENTS.md)：日程状态、时间边界和业务错误。
  - [`app/`](app/AGENTS.md)：应用服务、端口契约、DTO 和 JSON 边界。
  - [`clock/`](clock/AGENTS.md)：系统时间环境适配器。
- 依赖方向必须保持向内：`app` 和 `clock` 可以依赖 `domain`；`domain` 不得依赖应用服务、时钟实现或存储；存储实现通过 `app.ScheduleStore` 接入，不反向改变用例规则。
- 一次请求的当前时间必须通过 `Clock.Snapshot` 获取并复用；领域校验完成前不得触发存储写入等副作用。
- 对外返回必须使用应用层受控视图，不能直接暴露领域内部结构、数据库行或错误 cause。
- 修改日程规则、应用契约或时间读取行为时，必须同步检查对应子目录测试和跨层依赖方向。
