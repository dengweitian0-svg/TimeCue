# internal/storage/sqlite

- 本目录实现基于 `modernc.org/sqlite` 的 SQLite 持久化适配器，当前实现 `schedule/app.ScheduleStore`。
- 当前结构：
  - `db.go`：打开、初始化、外键启用、迁移和关闭数据库资源。
  - `migrate.go`：读取迁移版本、原子应用迁移和拒绝不支持的新版本。
  - `store.go`：日程创建、单条读取、ID 游标分页、数据库行转换，以及 `ScheduleUpdater` 和 `ScheduleDeleter` 的更新/删除实现。
  - `schedule_action_store.go`：整组取消/恢复的原子状态转换、幂等和提交后回读。
  - [`migrations/`](migrations/AGENTS.md)：内嵌的版本化 SQL。
  - `*_test.go`：验证迁移、创建/更新/删除事务、版本冲突、错误链、游标、资源关闭和端口契约。
- `OpenStore` 接收数据库路径、独立备份目录和非 nil logger，必须创建数据库父目录及备份目录，完成连接检查、每个物理连接的外键约束和迁移后才返回可用 `Store`；外键通过连接级 DSN 参数启用，当前通过单连接配置简化 SQLite 锁行为和显式事务观察。
- 已有数据库会先在独立探测连接中读取迁移版本并关闭连接；只有需要迁移时才在关闭状态下以 `<database>.YYYYMMDDTHHMMSS.nnnnnnnnnZ.bak` 形式独占创建备份。备份必须完整复制、刷新并关闭，失败时不进入迁移；迁移失败保留数据库和备份供手工恢复。
- 迁移的 SQL 执行和版本记录必须在同一事务中提交；任何失败都必须回滚；数据库版本高于本程序支持范围时必须拒绝启动，不能降级运行。
- `CreateSchedule` 必须在单一事务中完成插入、回读和提交，只有提交成功后才能向应用层返回成功；回滚失败必须与原始错误合并保留。
- `UpdateSchedule` 必须在单一事务中重新读取日程、检查允许的单次/重复边界和期望版本，执行带版本条件的 cron、截止日期、月末策略、单次开始/持续时间/身份锚点及开放状态更新、回读和提交；跨类型转换不得删除例外或提醒尝试记录。读取、更新、回读或提交失败都必须回滚，版本冲突必须返回 `STALE_REVISION`。
- 版本 2 追加可空 `until_date_local`（`YYYY-MM-DD`），版本 3 追加可空 `month_end_policy`（当前允许 `NULL` 或 `clamp`），旧迁移保持不变。创建和统一行扫描保存/读取这些字段；更新候选使用存在性标记支持策略显式清空。未携带字段、原始发生身份、Open 和创建时间必须保留，每次成功更新 revision 加一并更新审计时间。
- 版本 4 追加非空默认空字符串的 `notes`，并扩展 `occurrence_overrides` 的完整快照列；原有 `occurrence_local` 作为 `original_date` 的物理存储保持不变。版本 5 修复遗留单次 `cron IS NULL AND open=0` 为开放，并以触发器阻止未来非法单次状态。
- 仅持久化定义，不生成实例行，不新增 `frequency`、`next_at` 或结束时间列；日志沿用创建/更新事务提交后的 INFO 里程碑，失败向上返回由系统边界统一记录。
- `month_end_policy` 通过统一扫描和列表 DTO 映射返回；创建月规则时由领域候选携带 `clamp`，单次/日/周规则返回 null。
- 重复规则在日/周/月之间切换时，cron 与 `month_end_policy` 必须由同一事务提交；cron 未修改时策略保持不变，月转日/周必须显式写入 NULL。
- `UpdateSchedule` 只修改父日程定义，不删除或重建 `occurrence_overrides` 或 `reminder_attempts`；应用层可在同一版本守卫下读取并返回保留数量，合并结果始终按 `(schedule_id, occurrence_local)` 去重。重复转单次时允许同事务恢复 `open`，并清空不适用的 cron、截止日期和月末策略；单次转重复必须保持单次开放不变量。
- `CancelOccurrence` 在父 revision 守卫下将例外置为 `open=0`；无现有例外时写入空快照，已有完整快照只改变 `open`，重复取消不更新父 revision。
- `RestoreOccurrence` 在父 revision 守卫下将完整取消快照恢复为 `open=1`，或仅在候选明确要求且例外为空快照时删除取消行；没有实际状态变化时不更新父 revision。例外动作结果必须返回事务内父日程 `open` 状态。
- `CancelSchedule` 和 `RestoreSchedule` 仅接受重复日程；事务内重读定义并校验 revision，相同目标状态只读返回，实际变更只更新 `open`、`revision` 和 `updated_at_utc`，回读并提交成功后才返回。整组动作不得修改例外或提醒事实。
- `DeleteSchedule` 必须在单一事务中读取标题和版本、执行带版本条件的物理删除并提交；删除依赖外键级联清理关联记录，任一步失败都必须回滚，并在失败时保留已读取的标题。
- `recurring_e2e_test.go` 使用真实临时 SQLite 和可控时钟验证重复日程 JSON 生命周期、规则编辑、重开后计算一致性，以及计算和失败请求不生成实例记录。
- `occurrence_e2e_test.go` 使用真实 SQLite 验证例外移动、同刻多身份、跨日跨月、父截止收缩、整组编辑保留、重开一致性和级联删除。
- 日程读取必须复用统一的行扫描和时间解析规则；列表使用按 ID 升序的游标分页，并用 `LIMIT + 1` 判断是否存在下一页。
- 存储层负责数据库约束和持久化错误，不重复实现应用层的标题、端点和时间边界校验；新增字段时必须同步迁移、扫描、写入、DTO 映射和测试。
- 例外快照的完整性由数据库约束守护：本 Issue 写入的开放例外必须同时具备实际开始、正时长、标题和备注；父日程删除时通过外键级联清理例外。
- 数据库连接、事务和 rows 的关闭错误不得静默吞掉；扫描错误与 rows 关闭错误同时发生时必须保留两者；`Store` 必须接收调用方注入的非 nil logger，不得回退到全局默认 logger；`Store.Close` 的资源所有权由 `Store` 持有，调用方负责调用并处理返回错误。

- generation.go 为进程内日程事实版本提供查询和递增能力；成功提交的定义、例外和整组状态变化递增，幂等和回滚不递增，重启使用新的初始值。
- occurrence_query_store.go 按日程 ID 游标批量读取定义及例外快照，复用统一扫描逻辑，不生成或持久化发生实例。
- reminder_attempt_store.go 以稳定发生身份原子 claim 和终态回写提醒尝试。
- 版本 6 为 reminder_attempts 增加 (schedule_id, occurrence_local) 唯一身份和 claimed → submitted|failed|skipped 状态守卫；claim 与结果回写均为独立事务，回写失败不得覆盖或删除 claimed。
- 版本 7 仅为 `reminder_attempts` 增加可空 `processed_at_utc` 及待处理局部索引，不回填历史确认时间；发送状态和处理状态保持独立，状态回写只更新 `status`。
- `ListPendingReminderAttempts` 严格筛选 `status='submitted' AND processed_at_utc IS NULL`；`GetReminderAttempt` 可读取任意发送状态，`ConfirmReminderAttempt` 在单事务内只允许 submitted 首次写入，已确认返回首次时间，其他发送状态返回 `REMINDER_NOT_PROCESSABLE`。
- 确认事务必须提交成功后才向应用层返回，成功里程碑只记录稳定身份、是否首次确认和 UTC 处理时间；日程级 generation 不因处理状态改变而伪增。
- reminder_attempts 不保存通知正文快照。日程删除沿用外键级联，目标记录被删除后详情状态为缺失，不恢复已删除的提醒。
