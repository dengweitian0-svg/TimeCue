# Agent Loop

- `run.go` 装配生产模型客户端和六个正式日程工具，接入宿主准备、接纳与退出。`service.go` 管理会话、运行准入、取消和订阅。
- `recovery.go` 按已提交事实决定运行、模型的恢复动作及执行时机，`model_retry.go` 执行模型请求并沿保存的调用身份、正文及重试预算推进。
- `request.go` 在预算及创建前摘要阈值检查中使用模型适配后的最终正文。`compact_flow.go` 推进摘要和续写，原子提交有效摘要及下一普通调用或运行终态。
- `tool_loop.go` 推进已提交的 checkpoint，`tool_batch.go` 向 ToolFactory 提交批次与运行门禁，并采用其已提交进度。
- `event_batch.go` 保存流式事件批次，`persistence.go` 在保存失败时停止推进并重试终态，`usage.go` 从存储原始记录按需查询用量。
- 通过 Loop 的集成测试覆核准入、取消、模型、工具、事件、摘要、用量和持久化故障。

## 工程约束

- 初始化只读取恢复事实。宿主在截止时间内接纳后，Loop 才启动推进。需要模型请求的路径在实际发送前检查同一模型配置。
- 退出使用宿主提供的独立期限。已撤销工具仍在使用 App 或数据库时，等待实际返回后才通知宿主 LoopDone。
- 保存失败后仅公开已经提交的事件和终态。运行与恢复契约见[聊天说明](../../../docs/CHAT.md)。
