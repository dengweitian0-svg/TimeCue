# Chat 模块

- `tool_loop.go` 在正常 length 的回复/工具结果提交后创建 continuation=true 调用，默认每 run 5 次，按统一 chat.max_continue 热读并统计全部续写记录，不消耗普通轮数或原调用重试预算；未配齐原 ID 的工具结果不插入 user 请求。网络中断不触发长度续写，预算耗尽仅失败 run，保留实际成功调用。
- `progress.go` 统一生成后续请求：文字/思考续写保留 assistant、独立 user“继续未完成的输出”、下一 assistant；工具续写沿原 tool 错误消息，不额外插入 user。正文投影只拼接最后普通轮及其续写；恢复按实际普通请求消息前缀确定边界，不按模型主键或事件重放猜分组，不新增持久化字段。
- `argument_feedback.go` 仅为正常 length 的参数解析错误生成模型上下文反馈；闭合已有容器/字符串，省略未完成字段或字面值，不猜业务值，明确未执行业务且要求重新输出完整调用。原 model_call.output、tool_call.input/output/error、argument=null 事件均保持实际值；工具错误反馈与配对 checkpoint 同事务保存。
- 参数格式扫描以共享不可变栈记录轻量边界，只在验证候选时生成闭合内容；超过 encoding/json 的 10000 层嵌套限制时反馈 context_arguments=null，保留原解析错误及未执行说明。公共用例覆盖残缺字符串、数值/布尔字面值、转义、4096 层容器及超限片段。
- 字符串外连续空白只保留首个等价边界，字符串内部空白保持原文；扫描与全部候选校验共用 1 MiB 累计字节预算，在复制或校验候选前扣减，超限返回 context_arguments=null。公共用例覆盖 128 KiB 混合空白、字符串空白、扫描超限、多候选校验耗尽、原参数与错误保留及同批完整查询。
- 长参数回归在真实终态保存入口模拟四秒慢存储，使用事务实际回执与三十秒看门期限同步，再从公开接口核对终态、原参数及配对结果；存储错误直接报告，不将普通三秒轮询期限视为大参数落库契约。
- `continuation_test.go` 通过公共聊天用例、真实 SQLite/HTTP/日程验证正文与思考、混合工具批次、新调用 ID、上下文限定修复、预算耗尽、断流拒绝续写、重启原调用复用、普通轮边界及已有事件连续性。

- `tool_attempts.go`：单 run 协调器按当前并发上限调度可并行/串行尝试，默认 3；串行与其他有效尝试互斥，不承诺 FIFO，退避项不阻挡其他就绪调用。每次开始前热读超时，默认 30 秒、尝试内固定；超时立即取消、结算并释放名额，token 隔离迟到返回，工具 goroutine 仅报告事实，不修改完整进度。已开始尝试在用户取消时仍等待原结果或原期限。
- 工具首次开始固定当前 `tool_max_retry`（默认首次外 3 次）；仅 tool_timeout/tool_temporary_error 进入 5/10/20 秒指数退避，原记录、参数及适用键保持不变。retry_wait 保存错误/next_retry_at，不回填最终消息、不加入 completed_tool；实际重试前增加 retry_count，与 running/tool_use 原子保存。重启沿原期限与计数恢复，最后一次预算内执行仍允许启动。只有最终结果进入统一进度，全批完成才继续模型；取消退避统一保存 skipped/aborted。
- `tool_attempts_test.go`：公共服务、真实 HTTP 模型适配器/SQLite/正式日程及可控阻塞工具验证执行区间、动态缩扩容、串行互斥、默认退避、重启与预算固定、期限热读、超时及迟到结果隔离、错误分类、预算耗尽、退避取消和真实删除回执复用。
- 永久错误与参数错误用例以 30 秒作为终态观察看门期限，成功即返回，不改变业务超时/退避配置；核验实际执行次数、两次模型请求、四项公开结果的原错误类别与开始/结果事件配对。失败清理先输出运行、调用阶段及逐项工具状态，再停止服务；诊断读取共用两秒 context。
- 超时扫描每结算一个尝试即重新接纳结果队列，保存阻塞期间在原期限内返回的事实优先于下一超时裁定。正常退出期间取得的暂时故障或超时在剩余预算内保存 retry_wait/原退避期限，不写最终工具结果；退出不启动新尝试，重启沿原记录继续。用户取消或会话删除阻止重试，实际最终结果与取消跳过仍走统一进度。
- `tool_lifecycle_regression_test.go`：真实服务与 SQLite、可控模型/工具/保存边界验证慢超时结算不丢失其他及时成功，以及正常退出期间暂时故障/超时的原记录、参数、预算、期限、事件和重启接续。
- 取消与退出回归在真实取消持久化入口模拟五十毫秒慢存储，取消请求使用五秒看门期限并核验 cancelled 回执，终态允许三十秒观察；在途工具仍由实际开始/释放信号控制，实际错误、一次执行、零重试及原 ID 配对断言保持严格。
- 工具退避取消测试通过真实 WaitToolRetry 提交信号暂停协调器，确认取消后再释放收尾；不轮询竞争短暂 retry_wait。慢保存测试使用两个独立尝试，按实际返回信号与原 context deadline 构造阻塞窗口，不以固定休眠推断工具完成；清理时关闭 abort，解除保存与工具的受控等待，再等待服务退出。受控保存结束后允许显式 30 秒终态查询等待，该等待是测试看门期限，不改变工具超时、退避或运行性能契约；其他原有终态测试默认等待不变。

- `schedule_delete_test.go`：公共运行用例、真实模型适配器/SQLite/App 验证软删除、实际冲突与不存在错误、原 ID 的模型与事件配对、非法参数仍保存危险身份、拒绝模型填写后台键，以及业务已提交而 AI 结果未保存窗口的原身份、只读核对和回执复用。
- `tool_attempts.go` 依据 Registry 固定 dangerous 元数据首次生成 tool:{tool_call_id}:{uuid}，随 BeginTool 提交后经 context 注入执行；ToolCall 保存及恢复原键，不在统一进度中生成身份。查询、创建、修改仍为非危险，完整工具取消与只读回执核对由当前协调器提供，完整写入恢复策略由后续切片提供。

- `schedule_write_test.go`：公共运行用例、真实 SQLite/模型适配器与 App 正式入口验证创建、依赖结果分轮修改、提醒替换、周期暂停、无键重复创建、版本冲突/不存在、参数拒绝、批量部分失败、跨午夜实时解析，以及已提交时间/结果在恢复后的原样复用；另核验工具键 SQL NULL 和空业务 key 不登记回执。
- 写入 Registry 启用时，`request.go` 在有效上下文前加入固定日程助手提示，不改写 run.input，也不重复加入相同提示。要求完整唯一直接执行、缺失或歧义先澄清、依赖操作分轮、冲突不自动覆盖；创建/修改由串行工具执行，开始/回填/异常配对仍复用统一进度。完整写入恢复由后续切片交付。

- `progress.go`：集中模型回复接纳、调用开始/结束快照、旧格式历史接续、工具开始、单项结果及异常批次收拢的完整进度操作。ModelCall 进度字段是唯一事实来源，CheckpointState 仅承载版本 3 的 context/completed_tool/last_tool 磁盘格式；新调用重置工具事实，同调用恢复保留原事实。待提交快照复制消息、原始工具 JSON 与完成集合，提交失败不采用新进度。工具结果按接纳次序合并，完成集合按原 ID 配对；全部原请求取得结果才表达 tool_end，不决定下一步执行策略。异常收尾优先复用已提交或协调器实际取得的结果，再统一生成 skipped/aborted 或 tool_result_unconfirmed，沿正常单项结果规则配对。
- `progress_regression_test.go`：通过公开运行/会话用例、独立旧格式 SQLite 样本及真实接纳事务故障验证空 assistant 兼容、仅思考及原工具配对、退出恢复的说明去重、原始 output/usage 保留、未接纳工具的上下文隔离，以及新调用清空工具事实后跨回复同值 ID 的独立结果。
- `tool_loop.go`：模型回复接纳、工具批次与下一普通模型调用衔接；执行调度由 tool_attempts.go 负责。开始事务失败不执行业务；保存失败立即停止启动，收集已返回工具的实际结果，未返回工具不阻挡故障收尾，以 PendingTools 随终态事务仅重试持久化，不重执业务。取消缺失项统一在终态事务配对，正常退出保留未完成进度。
- `tools_test.go`：公共服务、真实 HTTP 适配器、SQLite 和 App 日程入口验证分块参数、查询规则/revision、列表数组、北京时间日期发生情况、参数/业务错误、重复 ID 拒绝、已接纳回复与结果的恢复复用，以及结果事务故障停止推进并原子保留实际结果。
- `tool_progress_test.go`：在真实回复接纳、部分结果及 tool_end 提交边界取得一致 SQLite 快照，通过公开用例重建运行，验证已接纳模型与已保存结果复用、原身份与参数、未确认查询预算和按真实接纳次序回填；独立版本 3 样本覆盖不同完成次序、任意 JSON 类型与恢复预算耗尽。
- `terminal_progress_test.go`：公开运行/会话用例、真实 SQLite 与可控上游 HTTP 验证三个进度位置的旧格式取消恢复、真实开始/结果/终态回滚、并行已返回结果保留、提交回执丢失后的最新事实回读、快照隔离、保存重试与重复终态幂等，以及接纳后正常退出恢复。

工具只从统一 Registry 的 Tool 接口执行，模型定义与预算使用相同序列化 input。正常完成的回复先保存 succeeded、原 output/usage、尾批与 model_call_end，再启动工具；非正常部分工具增量不执行、不网络重试，同一回复内重复 ID 整批拒绝并排除无法配对的有效历史。

每个工具实际开始时保存 running、参数原文的外层 JSON 字符串、关联、tool_start 和 tool_use checkpoint，不创建 pending。参数解析及 schema 校验在提交后执行；每个最终结果、原始 JSON output/error、tool_result、原 ID 的 tool 消息、completed_tool/last_tool 与 checkpoint 同事务保存，不生成工具专用 error 事件。开始与结果存储操作在事务内回读已提交进度，应用统一完整操作，成功后返回完整快照；协调器只采用提交结果，不逐字段构造进度或维护第二份完成集合。全部结果完成才进入 tool_end；不同模型回复允许复用同值 ID。恢复复用已保存结果，未确认的只读查询沿原记录有限重执行；不重发已接纳的模型回复。

- `contracts.go`：固定四字段回执、十字段概况、模型选项、分页事件、内外状态，以及模型端口和运行、会话、模型执行、工具事务、事件查询五个独立存储接口。
- `request.go`：从完整有效历史追加本轮真实输入，按完整序列化请求的 UTF-8 字节数统一估算预算；估算器供请求及后续工具结果复用，不作为 usage。
- `history_budget_test.go`：公共服务、真实 SQLite 和可控 HTTP 验证完整消息快照、工具配对、创建时间顺序、失败/取消的正文与 thinking、空输出、中断说明的请求前保存与恢复去重、上游与实际 input 字节一致、预算取整边界及原子失败重放；以既有持久化进度验证普通轮数、续写/摘要排除、同调用恢复和可配置上限。
- `service.go`：真实运行协调器；拒绝缺少幂等键或空白必填字段，持久化幂等优先于新建配置与准入门禁，同会话互斥、全局最多三会话并发；读取本地模型选项、处理持久化协作式取消、会话隐藏和单连接替换。恢复 wait_for_cancel 保留原调用身份，只保存已有事实并提交取消终态，不进入模型或工具执行；成功调用及已提交结果不被改写。
- `admission_test.go`：通过公共用例、真实 SQLite 及模型响应和事务故障边界验证并发同键只创建/启动一次、同会话竞争、跨会话三个名额、创建回滚、配置拒绝不留键、重放优先级、跨进程终态回执、取消收尾占用、启动占用重建及故障遗留超过三个未完成会话时的有界恢复。
- `service_regression_test.go`：预算拒绝后的连续对话、无输出恢复失败/再次退出的部分回复保留及非法 SSE 游标不替换原订阅的真实存储回归。
- `service_test.go`：通过公共 RunService/SessionService/ModelService、真实临时 SQLite 和可控上游 HTTP 验证流式持久化、重启、预算、取消及幂等。旧运行被后续运行取代的恢复用例在真实提交边界模拟慢存储，等待事务结果后通过公开接口核对终态、部分正文与模型请求次数；保存错误直接报告，不以普通用例的三秒轮询期限推断收尾失败。
- `event_batch.go`：串行合并流式增量，满五条或首条等待五秒提交；后续增量不重置首条期限。关闭批次后尾批交由退出或终态事务保存，保存失败停止模型推进。
- `events_test.go`：公共运行用例与真实 SQLite 验证批次期限、事务中途回滚、尾批及终态、正常退出恢复、分页追加、历史/实时交接、慢连接和旧订阅清理隔离。

请求实际 input、running 和 checkpoint 提交后才发送上游请求；结果与原始 usage、进度、终态原子提交。SSE 和分页读取相同持久化序号，断开只影响订阅。正常退出保存部分 output，保留 running 与原 checkpoint；启动先重建占用，再沿同一逻辑调用和原 input 后台重发。

新 run 沿按创建时间选出的最新终态运行完整 checkpoint.context 接续，不按模型调用 ID 拼接历史、不重新补回已覆盖原文；checkpoint 保留实际消息顺序、后端请求及工具配对。failed/cancelled 的有效部分 assistant（含仅 thinking）保持原文，完全无输出不伪造空 assistant；独立 user 中断说明放在旧轮及其配对结果之后、本轮真实输入之前，保存到实际请求及 checkpoint，恢复直接复用原请求。原始事件始终按 run 创建时间及 run 内 seq 查询展示，不用事件回放恢复执行。

创建前无可压缩历史且预算失败时，在创建事务中保存 failed、原输入、错误与 start/error/end，不登记 model_call、checkpoint 或 compact，不占执行名额。回执内部 NewlyCreated 仅区分 HTTP 首次创建和重放，不进入公开 JSON。普通轮数默认 20，可由统一 chat.max_rounds 配置；每次登记新普通调用前读取现有非 continuation 且不关联任何 compact 的逻辑调用数量。重试和未完成调用恢复不重复计数；已完成 tool_end 恢复沿完整快照登记下一调用，到达上限时仅失败运行，保留此前成功调用与进度。取消只读恢复遇到已终态调用时只结束 run，保留原调用与完整 checkpoint 工具配对。正常长度自动续写已接通；完整写入恢复及运行中摘要仍由对应后续切片交付。

创建互斥区覆盖幂等查询、配置与准入检查及真实创建事务；提交失败不登记运行占用或幂等键。幂等只比较同会话中的原始 input，provider/model 不参与比较；已删除会话优先拒绝。running 与 wait_for_cancel 均占名额，历史和订阅不占名额，正常终态保存成功后由唯一协调器释放；持久化故障耗尽遵循下述例外。

启动登记全部未完成运行，推进协调器共用三个执行名额；故障耗尽遗留的超额运行在内存中等待，不新增持久化队列或状态。排队运行仍保留会话占用与原键回执，取消或退出可直接保存已有事实，不发模型请求，也不等待其他模型完成。

执行存储通过 SaveEvents 原子提交部分响应和原始事件批次，Pause/Finish 同事务保存未提交尾批；序号由存储事务分配，不缓存尚未提交的序号。正常退出中的真实保存失败仍按 persistence_failed 收尾；退出导致请求登记取消不冒充存储故障。

缺少配置或 Key 不阻断启动与本地查询；拒绝真正新建，不回退固定回复。运行资源不依赖 HTTP 请求生命周期。内部 wait_for_cancel 与对外 cancelled 分开建模；正常长度自动续写已接通；完整写入恢复和运行中摘要由后续切片扩展。

- `model_retry.go`：同一逻辑调用的有限重试与 5 秒起始指数退避，只有无有效输出的超时、网络、429/500/503 故障可重试。每次实际请求前重读 Key 和超时，原 input 与 max_retry 固定；计划退避及请求前 running 均先保存再推进。
- `retry_test.go`：真实服务、SQLite、配置监听及可控 HTTP 验证重试成功、5/10/20 秒耗尽、零预算、部分输出、取消、退出/重启沿用原调用和最后一次许可，以及 Key/超时更新与预算固定。
- retry_count 在计划一次重试时增加，retry_wait 恢复沿用已计数的原计划及 next_retry_at，不额外扣次；未完成 running 的生命周期重发不增加网络重试次数。取消清除计划期限，退出保留 retry_wait。重试中间错误仅保存调用事实，最终错误与唯一 end 才进入公开事件。
- 退避期间删除 Key 或请求开始前取消时，终态同事务结算尚未获得结果的重试历史项，不遗留 running；对应测试沿公共服务与真实配置/存储验证。

- 用例按 ModelService、RunService、SessionService 分别注入；HTTP Handler 只使用相应窄接口，App 通过独立 Lifecycle 管理启动与停止。

- 终态保存失败后保留占用，按五秒间隔最多重试三次，仅重试持久化、不重发模型；耗尽释放资源但不伪造已落库终态。
