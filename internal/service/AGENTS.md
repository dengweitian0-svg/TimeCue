# 日程与提醒业务

组合日程、提醒的业务操作，提供规则计算和查询视图。

- `app.go`：业务服务与 RuntimeDatabase/HTTP handler 装配契约、固定目录运行路径、公开 RuntimeInfo、可选 OnReady 回调；App.Run 管理配置/日志/数据库/HTTP/调度/恢复生命周期、请求等待与退出清理，以及日程基础用例。
- `notification_loading.go`：调度存储端口和纯版本窗口计算，保留严格生效边界、重合去重及旧秒级排除。
- `scheduler.go`：单循环每 30 秒扫描前后各 30 秒、未来 1 分钟首提醒提交后加载、内存等待与完整分钟分组、成员失效、遗漏登记及回拨后重扫。
- `scheduler_test.go` / `app_test.go`：扫描/到点/取消、版本端点、退出等待及真实 HTTP 优雅窗口中的结果回填测试。
- `next_notify.go`：单次/周期规则校验、北京时间下一次触发计算及提醒生成；支持每天、每周、每月和短月月末处理。
- `schedule.go`：日程存储接口、日期安排与未来投影、历史去重、月历标记、组合快照和游标分页。
- `notification.go`：提醒存储接口、历史待确认查询、提醒详情与单条/批量确认。
- `notification_delivery.go`：完整分钟任务接纳、领取、开始资格重检、文案及实际成员冻结、原子结果回填、四次预算和 5/30/120 秒重试、明确执行者退出及只读运行/尝试成员视图。
- `recovery_candidates.go`：按单个历史有效版本有界展开，保留继续位置，不扫描多年空分钟；对应测试覆盖版本端点、重合去重及 500/501 条边界。
- `notification_recovery.go`：启动与运行间隙恢复、固定终点和运行内进度、批次交接、未开始旧分钟封存及完整 recovery 汇总；对应测试验证空历史和取消等待。
- `notification_members.go`：当前任务历史及 attempt 冻结成员分页、成员版本游标和恢复摘要，复用 OccurrenceView。
- `notification_delivery_test.go`：完整任务领取上限及未来任务拒绝测试；真实 SQLite 投递竞争、重启和重传测试位于 store。
- `next_notify_test.go`：规则解析与触发时间计算测试。

# 约束

- 通过窄 Repo/RuntimeDatabase 调用存储；main 注入具体适配器，App.Run 管理连接和日志生命周期。创建日程与首提醒使用联合事务，调度生成独立于投递与确认，历史触发按版本边界归属，暂停区间不生成。
- loaded 先提交再入队，到点快照及完整分钟事务提交后才开放分组；重扫/重启可补入 loaded，failed 重加载的许可与预算归 D2。扫描位置、分钟集合、队列及恢复间隙只放内存，Snapshot 返回副本，不持队列锁访问数据库。
- 正式写入成功后检查近期首提醒并使旧候选失效；内存版本保护阻止乱序旧回调撤销新任务，入队错误不撤销或伪装已提交规则。App.Run 取消并等待调度与恢复，在 HTTP 优雅窗口等待已接收请求后再关闭数据库/日志；请求上下文不随后台取消，结果仍可提交。业务层不导入 API 或具体 store。
- 周期规则使用固定 UTC+8，仅支持每天、每周日期列表、每月日期列表的五字段形式；下一次触发严格晚于基准时刻。
- 过去安排读取提醒事实，未来规则投影与事实按日程 ID/计划时间去重；游标绑定查询用途、日期、asOf 和排序边界。
- 确认针对明确提醒 ID，集合最多 500 条，去重并整批校验后原子提交；重复确认保留首次时间，不改写投递结果。
- 规则写入、删除、确认与 claim/start/results 共用 App.operations 的正式操作边界；Scheduler 的内存锁单独管理，存储端口不回调业务或调度。DeliveryService 只能由其所属 App 操作，不在多个 App 间共享。
- 分组、attempt、展示次数、成员快照及结果回执仅保存在当前运行内存。领取最多 20 个完整任务；有效 start 才消费展示次数。重复领取复用未开始身份，重复 start 返回原决定，回填只使用冻结成员；已成功结果不得降级。
- D1 以 RetryIDs 交付已到期 failed 候选，不自行改写状态；D2 首次接纳本运行任务时许可重加载，后续仅在预算和等待满足后许可 failed → loaded。重扫不重置预算，重启丢弃旧身份；当前分钟交 D1，更早事实交 D3 全期间恢复。
- 恢复从可证明版本及已有事实的最早边界扫描，固定各轮终点，每批最多处理 500 条历史提醒；运行内按提醒 ID 去重统计，暂停区间不生成，未知早期规则不猜测补造。批间释放 operations，不持调度内存锁访问存储。
- 遗漏窗口按整分钟触发点归属，空的亚分钟间隙不新建轮次；尚未到期的交接窗口继续保留。回拨后新建的 loaded 若落入已核验分钟，过期后交恢复，不重复该分钟已有成功记录。
- claim/start 先封存尚未有效开始的旧分钟，撤销旧 claim 并交汇总；已经消费过展示次数的任务保留身份、预算和回填入口。成员只归属一个待开始任务；整理完成前汇总不能领取，开始仅展示实际数量，结果只回填冻结集合。
- 连续遗漏将未有效开始的旧 recovery 汇总合入新轮并撤销旧身份，保留完整历史统计及成员；退役汇总从内存索引移除。已有效开始的汇总不扩充成员、不重置预算。
- 任务历史与尝试成员每页 50 条，游标绑定用途、任务、attempt 及成员版本；成员增加后旧续页返回冲突，旧运行身份失效。组合快照及 recovery 任务分页区分已整理数、未知/完整遗漏总数和当前可展示数，不把整理完成当投递成功。
- App 退出停止新领取及开始，已接收结果仍可回填。明确执行者退出保留已用次数，未知结果不伪造 failed；无租约和心跳，不能仅凭超时自动重新展示。

- RuntimeInfo 只表达本次运行身份、PID、HTTP 契约版本和已实现能力，不保存业务投递状态。OnReady 在启动检查及后台装配成功、HTTP Serve 进入接收循环后最多调用一次；取消或启动失败不调用，回调失败沿用资源清理。ready 不等待历史恢复，不解释 stdout 协议。
- HTTP Shutdown 的 5 秒窗口超时后记录诊断、关闭连接并取消请求；仍等待活跃业务和后台结束后关闭数据库，不承诺整个进程必在 5 秒内结束。退出在日志关闭前关闭并等待配置监听。固定端口测试使用 `-p 1` 串行执行。

- `schedule_change.go`：创建/更新正式操作，规范化请求摘要，在同一存储事务内校验旧版本与同类型规则、拒绝已到期单次改时、计算严格未来的首提醒。
- `schedule_mutation.go`：从正式操作结果生成受控变更摘要，记录版本、生效时间、调度规则、启停/删除/取消差异及首提醒；名称和说明只记录字段名，不包含文本。不额外读取数据库，不依赖 HTTP 或日志实现。原样提交保留版本递增并返回空差异；重放只描述原回执。
- `DeleteScheduleWithResult` 返回正式删除的前后态；`DeleteSchedule` 保留只返回错误的调用方式。存储删除端口返回 `ScheduleWrite`。

新版本创建/更新一律拒绝非分钟计划时间，不豁免原样提交的旧秒级规则。查询保留旧持久化事实，但不投影旧秒级单次；投递查询也排除该类旧规则。

日期触发页返回 `openScheduleCount`：在同一读取快照、完整事实与投影集合上按 Schedule ID 去重，统计当前启用、未删除、未取消的日程，包含已确认和未确认。单次没有独立 open 开关，按有效规则计入；周期必须 period.open=true。统计先于分页，首/续页共用完整总数，不与提醒行数或待确认数混用。
