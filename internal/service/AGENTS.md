# internal/service

- 本模块定义日程与提醒业务流程所需的存储接口；规则计算和业务用例由服务层组合，存储层负责已定义的原子状态约束。
- 删除日程采用软删除；已发生的提醒历史必须保留。
- `ScheduleRepo.GetScheduleByID` 将必填日程 ID 作为独立参数；存储实现直接满足服务层接口，不再使用转接文件。
- `NextNotify` 的业务目标是按日程 ID 检查状态、计算下一次触发时间并写入提醒；当前仅有接口草稿，尚未实现。
- `NewApp` 接收配置与 Repo 接口，不直接创建存储实现；数据库连接由入口层持有和关闭。
- 新增可导出函数及关键业务转换应提供中文注释。
