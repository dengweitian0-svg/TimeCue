# 日程与提醒业务

组合日程、提醒的业务操作，提供规则计算和查询视图。

- `app.go`：服务装配、日程基础用例与提交后的调度入队/失效钩子。
- `notification_loading.go`：调度存储端口和纯版本窗口计算，保留严格生效边界、重合去重及旧秒级排除。
- `scheduler.go`：单循环每 30 秒扫描前后各 30 秒、未来 1 分钟首提醒提交后加载、内存等待与完整分钟分组、成员失效、遗漏登记及回拨后重扫。
- `scheduler_test.go`：扫描、到点、取消、回拨重试和版本端点测试。
- `next_notify.go`：单次/周期规则校验、北京时间下一次触发计算及提醒生成；支持每天、每周、每月和短月月末处理。
- `schedule.go`：日程存储接口、日期安排与未来投影、历史去重、月历标记、组合快照和游标分页。
- `notification.go`：提醒存储接口、历史待确认查询、提醒详情与单条/批量确认。
- `next_notify_test.go`：规则解析与触发时间计算测试。

# 约束

- 通过 ScheduleRepo/NotifyRepo 及调度端口调用存储，连接仍由入口管理。创建日程与首提醒使用联合事务，调度生成独立于投递与确认，历史触发按版本边界归属，暂停区间不生成。
- loaded 先提交再入队，到点快照及完整分钟事务提交后才开放分组；重扫/重启可补入 loaded，failed 重加载的许可与预算归 D2。扫描位置、分钟集合、队列及恢复间隙只放内存，Snapshot 返回副本，不持队列锁访问数据库。
- 正式写入成功后检查近期首提醒并使旧候选失效；内存版本保护阻止乱序旧回调撤销新任务，入队错误不撤销或伪装已提交规则。业务层不导入 API 或具体 store。
- 周期规则使用固定 UTC+8，仅支持每天、每周日期列表、每月日期列表的五字段形式；下一次触发严格晚于基准时刻。
- 过去安排读取提醒事实，未来规则投影与事实按日程 ID/计划时间去重；游标绑定查询用途、日期、asOf 和排序边界。
- 确认针对明确提醒 ID，集合最多 500 条，去重并整批校验后原子提交；重复确认保留首次时间，不改写投递结果。

- `schedule_change.go`：创建/更新正式操作，规范化请求摘要，在同一存储事务内校验旧版本与同类型规则、拒绝已到期单次改时、计算严格未来的首提醒。
- `schedule_mutation.go`：从正式操作结果生成受控变更摘要，记录版本、生效时间、调度规则、启停/删除/取消差异及首提醒；名称和说明只记录字段名，不包含文本。不额外读取数据库，不依赖 HTTP 或日志实现。原样提交保留版本递增并返回空差异；重放只描述原回执。
- `DeleteScheduleWithResult` 返回正式删除的前后态；`DeleteSchedule` 保留只返回错误的调用方式。存储删除端口返回 `ScheduleWrite`。

新版本创建/更新一律拒绝非分钟计划时间，不豁免原样提交的旧秒级规则。查询保留旧持久化事实，但不投影旧秒级单次；投递查询也排除该类旧规则。

日期触发页返回 `openScheduleCount`：在同一读取快照、完整事实与投影集合上按 Schedule ID 去重，统计当前启用、未删除、未取消的日程，包含已确认和未确认。单次没有独立 open 开关，按有效规则计入；周期必须 period.open=true。统计先于分页，首/续页共用完整总数，不与提醒行数或待确认数混用。
