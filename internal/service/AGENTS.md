# internal/service

- 本模块定义日程与提醒业务流程所需的存储接口；规则计算和业务用例由服务层组合，存储层负责已定义的原子状态约束。
- 删除日程采用软删除；已发生的提醒历史必须保留。
- `ScheduleRepo.GetScheduleByID` 将必填日程 ID 作为独立参数；存储实现直接满足服务层接口，不再使用转接文件。
- `NextNotify.Next` 按日程 ID 查询状态，计算严格晚于 `after` 的下一次时间并幂等写入提醒；无下一次时返回空提醒和空错误。调度器以已处理提醒的计划时间推进。
- `App.CreateSchedule` 复用纯规则计算并通过联合事务创建日程及首条提醒；单次日程时间必须晚于创建时刻，暂停周期日程不生成首提醒。
- `App.AdvanceNotification` 先查提醒所属日程；仅周期日程可推进，单次日程返回 `ErrNotPeriodSchedule`。
- 周期规则按固定 UTC+8 北京时间计算，仅接受每天、每周日期列表、每月日期列表三种五字段形式；月份固定为 `*`，星期日为 `7`。短月超出日期改在月末触发，多条规则取最早时间。
- 服务返回的业务时间带 `+08:00` 偏移；单次日程保留原时间点并以北京时间表示。
- `NewApp` 接收配置与 Repo 接口，不直接创建存储实现；数据库连接由入口层持有和关闭。
- 新增可导出函数及关键业务转换应提供中文注释。
